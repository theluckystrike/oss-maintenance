What the audit checks

Every string in every locale, compared with the same key in your source language.

  • Placeholders that were dropped, renamed, translated or added: {{name}}, {name}, %{name}, %s, ${name}.
  • ICU messages: plural and select keywords that got translated, braces that don't balance, and whether each message parses and formats with the values your code passes.
  • Rich text and Trans tags like <0>, <b> and <a> that were lost, left unclosed or shown as raw text.
  • Brand names typed into a translation where your code passes a variable. That's the white-label leak.
  • Keys your code asks for that the locale files don't match, and findings on keys no code uses any more. Those dead keys are listed, not fixed blindly.

The string checks run by script on every locale. Each finding is then checked by hand against the code that calls it, so the PR only changes what users actually see.

What you get

  • A written report. Every finding with locale, key, the current text, the fixed text and what the user sees today.
  • One PR that fixes every objective bug: placeholders, syntax, tags and brand leaks. Wording only changes where a value has to fit into the sentence.
  • Checked with your repo's own tooling (lint, translation validator, JSON parse) and a render test that formats every changed string with real values before and after.
  • If your translations live in a TMS like Crowdin, Lokalise, Lingo.dev or Tolgee, you get the fixes as a file to import there instead of a PR, since edits to the repo would be overwritten.
